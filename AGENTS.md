# Operating rules for coding agents

This file is canonical for every coding agent working in this repository, whatever the harness. `CLAUDE.md` points here. If the two ever conflict, this file wins.

You are building a client-facing demonstration that will be scrutinised by an experienced technical lead at a Dubai property developer. He will try to break it. Assume every shortcut you take is the one he finds.

## Read before you write

1. This file.
2. `docs/06-build-plan.md` - authoritative on what is in scope, faked, or deferred this week.
3. `docs/01-architecture.md` - module boundaries and the ADRs.
4. `docs/02-data-contracts.md` - before writing any type or schema, check whether it already exists there.
5. `docs/03-guardrails.md` and `docs/04-voice.md` for anything touching validation or audio.

Do not start coding from the README alone.

## The five invariants

Violating any of these is a defect regardless of whether tests pass.

**1. The model never sources facts.**
Project names, prices, unit sizes, handover dates, payment structures and amenities come from `data/inventory.json` only, loaded and validated through `agent/src/ambassador/inventory.py`. If a buyer asks about something not in inventory, the correct behaviour is to say so and offer a human. Never let the model fill a gap from training data.

**2. The model never does arithmetic.**
Down payments, instalment amounts and any other derived figure are computed by pure functions in `inventory.py` at load time and serialised into the prompt alongside the source figures. Derived figures are computed, never hand-authored - a hand-typed derived number is exactly the class of error this system exists to prevent. If you catch yourself asking the model to calculate, stop. If a buyer asks a question that needs a computation the system has not pre-computed, the designed answer is a refusal plus escalation, not model maths.

**3. Every model output is validated.**
Structured payloads parse through Pydantic. Spoken sentences pass through `guardrails/pipeline.process_sentence()`. Unparseable output triggers one repair retry, then a composed fallback. Never render or synthesise unvalidated model output.

**4. Guardrails are code, and ordering is enforced by types.**
Guardrails inspect digits; verbalisation destroys digits; audio cannot be retracted. Therefore: guardrails, then verbalisation, then synthesis. The pipeline enforces this structurally - `verbalise()` accepts only a `ValidatedSentence`, and the TTS adapter accepts only a `SpeakableText`. There is exactly one public function that produces speakable text: `process_sentence()`. Do not add another path, and do not weaken the types. A test asserts the ordering; do not delete it.

**5. Escalation is a feature.**
`escalate` renders a designed state and composed speech, not an error. The demo deliberately shows the agent refusing to guess. Treat that path with the same polish as the happy path.

## Stack

- **Agent**: Python 3.12+, managed with `uv`. LiveKit Agents is the voice framework (ADR-005; Pipecat is the documented fallback). Do not hand-build VAD, endpointing, barge-in, cancellation or transport.
- **Core**: `agent/src/ambassador/` is pure Python with zero framework imports (ADR-002). Pydantic for validation, pytest for tests. The core must remain runnable and testable with no voice stack installed.
- **Web**: Next.js 15 + React 19 + Tailwind, demo surface only. The UI makes no model calls.
- **Data**: language-neutral files in `data/` (JSON and YAML), consumed by the Python core and reviewable by non-engineers.
- No database. In-memory session state. `STUB:` the CRM write behind an interface.

## Hard rules

- **Never call an LLM, STT or TTS provider from the browser.** All provider calls happen server side: in the Python agent for the voice path, in Next.js route handlers if the web tier ever needs one. API keys live in server-side env only.
- **Never hardcode a secret**, including in test fixtures.
- **Never invent inventory.** Tests use `data/inventory.json` records or fixtures in `agent/tests/fixtures/`, never new entries in the production file.
- **Never resolve a `VERIFY:` marker on your own authority.** Leave the marker and surface it in your summary.
- **Never write guaranteed-return language** into prompts, UI copy, sample content or fixtures. Not "guaranteed 8% yield", not "assured returns", not "risk-free". Regulatory, not stylistic.
- **Never let a turn end in silence.** Every failure path in the voice session resolves to composed, localised speech. A caller who hears nothing hangs up.
- **Never write verbalisation, disclosure or prohibited-pattern copy for a language you do not speak.** Mark it `VERIFY:` for native review. English is the only language the build team self-certifies.
- **Do not add dependencies** without noting the reason in your summary. Every package is a question the tech lead may ask.
- **Do not build what the framework provides.** VAD, endpointing, barge-in, cancellation, transport, reconnection: LiveKit's job.
- **Do not build anything marked deferred in `docs/06-build-plan.md`.** If a task seems to require it, stop and say so rather than expanding scope.
- **Provider swappability for the voice path is framework plugin configuration**, not a hand-rolled abstraction. Do not write a custom LLM/STT/TTS adapter layer inside the agent; select providers in config (ADR-006).

## Coding conventions

- Pure functions in the core: no I/O in guardrails or verbalisation, no env access outside config loading. This is what makes "the model never does maths" provable.
- Types once: Pydantic models in `schemas.py` are the source of truth. Do not hand-write a parallel type.
- Python: type hints everywhere, `pytest` for tests, no `Any` where a real type exists.
- Web (when built): named exports, server components by default, `'use client'` only where interactivity requires it.
- Copy is sentence case. No exclamation marks anywhere in the product voice. No emoji. Binghatti sells restraint.

## Definition of done for any task

- [ ] Types come from `schemas.py` / `docs/02-data-contracts.md`, not invented in place
- [ ] Pure logic covered by unit tests; guardrail and derivation code requires 100% branch coverage
- [ ] Any new model interaction has at least one entry in the eval set (`docs/05-evals.md`)
- [ ] No new `VERIFY:` marker silently resolved
- [ ] `cd agent && uv run pytest` clean
- [ ] Web work: `cd web && npm test && npm run typecheck && npm run lint && npm run build` clean
- [ ] Web work: reduced motion respected, keyboard focus visible, works at 375px width

## What "good" looks like for this client

Restrained. Binghatti's brand is architectural precision, not exuberance. Monochrome base, one metallic accent used sparingly, generous whitespace, no gradients, no rounded pill buttons. If a screen looks like a generic SaaS dashboard, it is wrong.

## Project learnings

Append corrections and non-obvious project facts here as they are learned. Newest first.

- 2026-09-01: **a lazy `from livekit.plugins import x` inside a function is a THREAD-AFFINITY BUG, not a style choice.** Importing a plugin module registers a plugin, and `livekit/agents/plugin.py:register_plugin` raises `RuntimeError("Plugins must be registered on the main thread")` if that happens anywhere else. Console mode runs the job in a worker thread, so #46's default flip onto `stt_factory.build_stt`'s lazy Deepgram import crashed the job AFTER the agent had fully constructed - last event `lexicon`, no `stt_enabled` - while `STT_PROVIDER=openrouter` still booted, because that recogniser is our own class and registers no plugin. Console mode is the venue plan B (docs/06-) and the day-1 gate path. Import plugins at module scope, where registration happens once on whichever thread first imports the adapter (the main one, at worker boot); if a lazy import is ever genuinely needed, do it from `prewarm`, where the main thread is guaranteed. Rule enforced for the whole adapter by `tests/test_plugin_registration.py`. **The bigger finding is why 747 tests were blind to it: every test runs on the main thread, and any test that builds the node there caches the module, so an in-process check passes vacuously afterwards.** A test for anything thread- or import-ordering dependent has to run in a FRESH interpreter (subprocess) or read the source; the same blindness applies to anything that only misbehaves once a worker boots.

- 2026-09-01: **whose figure is it - decide by SEGMENT, never by distance or by binding a marker to a figure.** Issue #25 took three review rounds and every finding was a SCOPE error, not a logic one. The two defects: `find_budget` claimed any figure carrying a currency or a multiplier, so "the listing says AED 750,000" and "Is it 750k?" were read back as the buyer's budget (and a confirmed figure SETTLES the policy, suppressing every later real mention); and `_BUDGET_UNITS` listed `k|m` where neither could match, because `extract_figures` FOLDS the multiplier into the surface ("800k") and `\bk\b` needs a boundary between "0" and "k". The three designs it took, and why the first two failed, is the transferable part. (1) A character window - source word within 14, keyword within 30 - lost a budget to one inserted modifier ("My budget after checking your website is AED 750,000"). (2) Marker-to-figure binding let the second price of a quoted RANGE escape ("or AED 800,000"), and binding "forward to the next figure" claimed the wrong one when ownership FOLLOWED its amount. (3) What holds: split the utterance into SEGMENTS at sentence punctuation, contrastive conjunctions (`but`, `however`, `though`) and a comma followed by the buyer talking about themselves or by a coordinating "and" - then ask five questions of each segment. A source word or a question opener FRAMES what follows it in its segment (direction matters: "I have 2 crore, what is the price?" is a budget). Ownership is a first-person ANCHOR plus a money TERM anywhere in the segment - two lists, never phrases, because a phrase list misses "I can ONLY spend" and its length changes which figure it reaches. Only ownership restores a quoted figure, never a plain budget keyword, because "up to" lives inside "prices go up to AED 900,000". An affordability cue cancels a question opener but NOT a source word. A dimension word withholds only the genuinely ambiguous unit - `m` is millions and metres - because suppressing every amount near a room lost "I have AED 800,000 for a room". And a budget keyword may only mark a figure in its own segment. (4) The lists that WITHHOLD can only ever lose a real budget, which is the expensive direction, so every one of them ships with a base-versus-branch differential over a corpus organised by SHAPE CLASS. Twice a corpus of strings passed while the shapes it lacked regressed - dimension-plus-plain-currency, third-person ownership words, postposed ownership, comma-plus-contrast. A corpus is only as good as its shapes.

- 2026-09-01: **a generated completeness report can only ask for what its SOURCE SET classifies, so a miscategorised item vanishes from it silently - and the fix belongs in the classification, not in the template.** The reviewer packet's whole claim is that it cannot go stale because it is derived from the loaders; it still failed to ask for Binghatti's hotline for weeks. `spoken_form_gaps` checks `currency_amounts` on purpose, so nobody is walked into authoring "four hundred and twenty dirhams square feet" - and 80015 is a non-currency `amount`, so it left the packet with the square footages. Every piece was individually right. The two cases are opposites and the set could not say so: for a square footage the digit fallback is CORRECT and an authored form is the defect, for a phone number the digit fallback IS the defect. So `AllowedFigures` now carries `identifiers` beside `currency_amounts`, populated from the whitelist's own `kind`. **When a generated document is missing something, ask what set it iterates, never what the template says.** Three mechanical consequences worth reusing. (1) A gap check and the runtime lookup must use the SAME key or an authored value closes the gap and is never spoken: `identifier_gaps` keys on FigureKind `"amount"` because that is what `figures._classify` returns for a bare five-digit integer, there is no `"identifier"` FigureKind, and a test authors a hotline form and asserts `verbalise()` actually emits it - mutate the key and that test dies, which is the only reason the claim is worth anything. (2) A data row that records a form is OWED (`spoken:` absent plus a required `verify:`) must load as ABSENT so it fails towards the digit fallback, and an EMPTY `spoken` must be REFUSED rather than treated as absent - otherwise a typo silently downgrades a language that used to speak, which is the same failure wearing the safe-looking clothes. (3) A label printed beside a generated value has to be generated too: "Binghatti's toll-free hotline" typed next to the number reads correctly today and is wrong the day a permit number is whitelisted, so it comes from the whitelist's `why`. Also, `prerolls.yaml` is the THIRD file here to be configuration in appearance and a document in fact (after `disclosures.yaml` and `lexicon.yaml`); it has a loader now, playback on a slow turn is still unwired, and an unauthored language deliberately gets no filler rather than the English one - the opposite of the disclosure's fallback, because an English acknowledgment inside an Arabic call is a seam the buyer hears rather than one it hides. Two tooling traps found the same day: `test_no_module_restates_the_language_set` greps `tests/` as well as `src/`, so writing `for lang in ("en", "ar", "hi")` in a TEST fails the suite - derive it with `typing.get_args(Language)`; and `ruff format` is NOT a gate in this repo (37 files predate it, `ruff check` is the gate), so reformatting on the way past drowns the diff.

- 2026-09-01: **Fish's public catalogue is readable with no key and no spend, and reading it before auditioning changes what you shortlist.** `GET https://api.fish.audio/model?page_size=30&page_number=N&language=xx&sort_by=score` needs no auth, and every item carries a public `samples[0].audio` preview, so a voice shortlist can be assembled and listened to before a single paid character is synthesised. Two findings that came out of doing that and that no amount of listening would have surfaced. The model record carries a `licensed` flag and `licensed=true` is an honoured filter: it returns exactly **seven** voices across the whole public library, all Japanese, so **nothing in English, Arabic or Hindi is licensed** and the commercial question is not answered by choosing carefully from the library. And the top of the Arabic and Hindi catalogues by both score and usage is clones of identifiable real people - a serving head of state, a member of the Saudi royal family, named commentators and streamers - every one of which scores well on the calm-professional register we want, so a shortlist built on register alone walks a likeness problem into the client's boardroom. `Fish Official` first-party voices exist for English only (zero in the top 300 by score for `ar` or `hi`). Candidates and their previews are in `docs/voice-shortlist.md`; `source=` is silently ignored as a filter, unlike `licensed=`.

- 2026-09-01: **an ADR that picks a default and a `_resolve(..., default)` that disagrees is a silent drift class - and this repo had it twice in one block.** ADR-017 says Deepgram nova-3 IS the recogniser and openrouter "stays selectable, but is not the default"; `config.py` defaulted to `openrouter`, `agent/.env.example` shipped it, and `docs/01-`'s own env block still cited ADR-015 for the same line. So a fresh checkout, CI, and anyone who copied the example ran the RETIRED recogniser - p50 1081ms after endpoint against 258-327ms, "Binghatti" heard as "Bint Jbeil", figures as words that ADR-011's confirmation cannot parse - and nothing failed, it was just four times slower. When an ADR names a default, grep for every place that default is written down (`_resolve` calls, `.env.example`, the docs' env block) and pin the shipped example with a test that LOADS it: `load_settings(EXAMPLE_ENV).stt_provider` is the operator's actual path, and a comment claiming the default cannot be wrong the way code can. **Corollary worth reusing: a default change that makes a credential newly required must ship the remedy in the failure.** `missing_credentials_error` in config.py names the variable, what it is for, and all three ways out (add the key, select the retired path on the existing key, or run text mode) - composed in config.py rather than at the raise site in `entrypoint`, because entrypoint is untestable and an error message nobody can test is one nobody notices going stale. It still echoes no value, which `missing_for_voice`'s own contract requires.

- 2026-09-01: **the TTS audio format picks which of two framework paths runs, and the wrong one fails by SOUNDING wrong.** `AudioEmitter.initialize` branches on the mime type: `audio/pcm` and `audio/raw` go to `AudioByteStream` (a plain framer), everything else builds a `codecs.AudioStreamDecoder` plus a decode task, which the framework's own comment there calls fragile across flush boundaries - and sentence-level flushing crosses one every sentence. `livekit-plugins-fishaudio` defaults `output_format` to `wav` and we never set it, so we were on the decoder path by omission; `adapter/tts_factory.py` now asks for `pcm`. Two vendor facts it rests on are PINNED by tests rather than trusted: Fish's default sample rate is 24000 for pcm and wav alike (so no resampling change - if a release splits them the session silently resamples), and `NUM_CHANNELS = 1`, because the raw path frames bytes as s16 at the declared rate and channel count. **No test in this repo can clear an audio format change**: a mismatch produces noise and raises nothing, so the ear check is a human step and must be stated as one. General point: `entrypoint` is untestable (transport, worker, real credentials), so anything chosen there is unprotected - move a choice into a small factory beside `build_stt` / `build_llm` and the revert-by-omission becomes a failing test.

- 2026-08-31: **a green `npm test` is not a green `tsc`, and in `web/` they fail apart.** Vitest transpiles types away rather than checking them, so two suites ran green immediately after a component prop was made required without updating the two call sites in the tests; `tsc --noEmit` failed on both. The runner said the code worked while the compiler would have refused to build it. `npm test`, `npm run typecheck`, `npm run lint` and `npm run build` are four separate gates and all four are in the definition of done above. Corollary worth keeping: if a change to a shared type or signature breaks no test at all, that is evidence the tests are not typechecked, not evidence the change was safe. Two more `web/` traps found the same week. The `next` scripts pin `NODE_ENV` themselves and that is load-bearing - `next build` is a production build by definition, and inheriting a non-production `NODE_ENV` (some agent shells export `NODE_ENV=development`) makes it prerender `/404` from the dev pages-router error component and fail with `<Html> should not be imported outside of pages/_document`, an error that names a pages-router problem the app does not have. And `server-only` throws under vitest, because vitest does not apply the `react-server` export condition; it is aliased to an empty stub in `vitest.config.ts` and still does its real job in `next build`.

- 2026-08-31: **a promise the MODEL has to keep is not a mechanism, whatever the wording - and temperature 0 does not make it repeatable.** Fifth instance of promise-without-routing, and the one that settles the method rather than the instance. #31 put `escalate_to_human` in the regeneration instruction's leading imperative and it measured 3/3 en, 3/3 hi, **1/3 ar**; the three Arabic samples were byte-identical requests at temperature 0 that disagreed with each other (issue #33), so there is no wording that makes the promise provable and no rewording worth trying. The rule: if a behaviour is load-bearing, put it in code and let the prompt be the nice-to-have. `AmbassadorAgent._backstop_regeneration` is the structural version - a regenerated reply that ends the turn stating no figure has refused by construction (the model was just told its figure was not in the inventory), and a refusal promises a colleague, so it routes one deterministically. Scoped to the regeneration invocation: a first-pass reply with no figure is ordinary conversation. It does NOT check whether the model called the tool, because the tool executes after `llm_node` finishes and cannot be observed there - requiring a signal you cannot see is the fail-open direction, and #31's notify-once-per-turn guard collapses the two requests anyway. **Convention worth reusing: every detection that gates a safety action must state which way it fails.** This one fails towards routing - a false positive costs one redundant ambassador task (deduplicated to one per turn), a false negative is the defect itself - so an unreadable sentence, and the figure extractor raising on itself, both count as "no figure stated". Detail: `states_a_figure` lives in `ambassador/figures.py` (both the adapter and the eval twin need it) and deliberately ignores `count` figures - the documented 0-12 exemption - because "there are 2 layouts" answers nothing about money and must not read as a corrected answer. Remaining open on #33 and NOT ours: `build_llm`'s temperature-0 comment and docs/07-'s "three consecutive identical runs" both rest on a determinism premise that is now disproved; rewording that to outcome-determinism is the human's demo-strategy call.

- 2026-08-31: **ordering the confirmation policies is not the same as deciding who owns a reply, and a same-size source edit can invalidate a whole mutation run.** Two lessons from the PR #23 review round. (1) With a budget question and a project question both live, precedence alone discards answers in one direction and steals them in the other - "Yes, and my budget is 2 crore" lost the Yes, and the "Dirhams" that answered the budget was charged to the project as a failed attempt. The rule that works is OWNERSHIP: a reply belongs to the question asked most recently, other open questions are SUSPENDED (not read, so they cannot be answered by accident or lose an attempt), fresh mentions are read only by policies with nothing open, and a suspended question is re-asked afterwards having consumed nothing. It lives in `ambassador/confirmation.py`, is pure, and the eval harness shares it instead of keeping its own copy of the ordering. Related: any deterministic handover must quiesce EVERY policy by abandoning it, not by a flag each read site consults - a guard is one site away from being forgotten, and the forgotten one resumed a four-turn-old budget question after the agent had already said it was bringing in a person. The model's own `escalate_to_human` deliberately does not quiesce: it fires on ordinary turns. (2) Python bytecode caches are keyed on (mtime, size), so an in-place edit of the SAME LENGTH inside one filesystem timestamp tick leaves a stale `.pyc` and the edit never runs. `_MIN_TOKEN = 3` -> `1` is the same length; the experiment reported "no behaviour change" twice about code that was never loaded. Any mutation harness must clear `__pycache__` and set `PYTHONDONTWRITEBYTECODE=1`, and must not run against a worktree anything else is testing in - a background sweep that restores files between runs will hand a concurrent test run somebody else's mutant.

- 2026-08-31: **fuzzy name matching against this inventory has two traps, and both are silent.** (1) Every project name shares the token `binghatti`, and every recogniser mangles it, so a scorer that rewards similarity alone either matches the bare brand word to a random tower or - worse - lets `binghatti` (similarity 1.0 inside "Binghatti Skyrize") outscore the two-token name and suppress the very match the confirmation exists for. Rank candidates by similarity but compare them against decoys by COVERAGE: how much of the utterance a key explains. The same rule decides the tie between a project's full name and its one distinctive token, which both hit 1.0 on a clean utterance; keeping the shorter one reopened the suppression bug. (2) `data/inventory.json`'s `area` values collide with project names (`Binghatti Circle` sits in Jumeirah Village Circle), so area names and shared tokens have to be scored as decoys or the agent asks whether the buyer's ADDRESS was a project. Thresholds were calibrated against the transcripts ADR-015 actually measured plus 46 ordinary buyer utterances, and the floor sits at 0.68 because "budget" scores 0.615 against "bugatti" - a lower floor turns the budget policy's own opening line into a project question. Also: the yes/no/negator word lists in `data/currencies.yaml` are not about currency and are now read by two policies; the file name is the trap, not the contents.

- 2026-08-31: **the promise-without-routing rule converges here, and it covers text we send the MODEL, not just text we speak.** Fourth instance (PR #20's `hands_over`, F2's fallback copy, now F8's regeneration instruction). The new layer: `REGENERATION_INSTRUCTION` told a blocked model to "offer a human ambassador" and named no tool, so the promise was made by the MODEL's own reply and nothing routed. The rule is therefore: anything that can end with a colleague being promised - product copy in `data/`, a prompt constraint, or a regeneration instruction - must name `escalate_to_human` or route directly. **And an English control run cannot prove it**: English called the tool from habit (1/1) while Arabic and Hindi satisfied the words and routed nobody (0/2), so a tool-call behaviour claim needs a run per shipped language. Shape detail, extending the 2026-08-28 note: the defect was POSITION, not absence - put the tool-naming imperative in its own sentence after the declarative context and before a trailing prohibition (constraint 3's shape), never tacked onto the tail of another clause, and keep "reply again correctly" ahead of it or the model refuses figures it holds. Two mechanical consequences: `REGENERATION_INSTRUCTION` now lives in `ambassador/prompts.py` because the adapter and the eval harness both need it and the harness cannot import `adapter.agent` in a core-only run - it was hand-copied, which is how a regeneration fixture measures a prompt nobody ships. And naming the tool there makes a DOUBLE handover expected: a retry that calls the tool and still states an unallowed figure also gets the composed fallback, so two paths ask for a human in one turn. `TurnTracker.record_escalation` now allows one handover per TURN (the flag is on the tracker, not the agent, because a buyer may need a human twice in one call) while `record_tool` still records every request - the notification is deduplicated, the audit is not.

- 2026-08-31: **the numeric guardrail's regex is assembled from data now, and three of its failure modes are silent.** All three were found by execution while closing the issue #8 bypasses, and none is visible by reading the pattern. (1) A SYMBOL must never take a trailing `\b`: `%\b` FAILS at the end of "20%" because nothing follows it, so while symbols and words shared one boundary rule every trailing percentage reclassified as a bare amount and was checked against the wrong set. Build symbol and word alternatives separately. (2) `\b` also fails after a word ending in a COMBINING MARK, which Devanagari "करोड़" does (the nukta U+093C is not a word character), so the crore claim stayed an exempt count even with the multiplier data present. Any data-supplied token uses `(?!\w)`. (3) An EMPTY alternation matches the empty string at every position, so an empty `percent` list makes every figure a percentage and an empty currency list makes every figure money - that scrambles classification rather than merely widening it, which is not the safe direction, so `figures.load_numerals()` rejects both at start-up. Related: a group separator inside a number must be REQUIRED to be followed by digits (`\d+(?:[,sep]\d+)*`), never merely allowed (`\d[\d,sep]*`) - the lax form captured a trailing sentence comma into the surface, and because the year branch inspects the surface, "Q4 2026," reclassified an ALLOWED year as an unallowed amount and blocked a correct sentence. Fix that class upstream of classification, not by stripping punctuation afterwards; there is then nothing to strip and the `_NUMBER_RE` boundary rules stay untouched. Finally, `data/numerals.yaml` carries `ar`/`hi` word lists that are EMPTY and `VERIFY:`: a magnitude written in pure Arabic or Devanagari script is still unread, that gap is disclosed in `docs/03-`, and `figures.languages_covered()` reports the true coverage.

- 2026-08-31: **copy that promises a human must route one, and the promise is in the DATA file, not the code.** Eval F2 (PR #24's harness): the composed fallback speaks `data/fallbacks.yaml`'s "let me put you through to one of our ambassadors" and `record_fallback` only appended a chunk and emitted an event - so the buyer waited for a call nobody booked, on the one path where the model by definition did NOT call `escalate_to_human` (the fallback fires because the model's output was unusable). Third instance of this shape after PR #20's `hands_over` defect, so the rule is now general: before wiring a recovery, READ ITS COPY and route every line that promises a person. The fallback routes (via `_speak_fallback`); the BRIDGE deliberately does not, because "let me be precise about that figure rather than guess" promises nothing and the turn carries on - routing it would page a human on every recovered sentence. `_tracker_sink`'s `on_fallback` is a required keyword argument for the same reason: a default of `tracker.record_fallback` is the defect, reachable by omission. Two knock-ons worth knowing: the eval harness in `src/evals/runner.py` is a hand-maintained TWIN of the adapter's recovery policy and has to be changed in the same commit or its rows measure the old behaviour; and `happy.year-followed-by-a-comma` now fails a THIRD assertion (`escalated when it should not have`) because the comma defect reaches the fallback, which is the same bug reported more completely, not a new one.

- 2026-08-31: **the framework measures more than it reports, and reports some of it as zero.** Two traps found wiring issues #18 and #7. (1) `EOUMetrics` already carries the endpointing number the budget table calls "never measured" - but it is built as `info.metrics.end_of_turn_delay or 0.0`, so a stage the framework could not measure arrives as a 0.0 rather than a None. Taken at face value that puts an instant endpointing on the latency meter; `events.py:_unflatten` reads a zero back as "not measured". Note also that `end_of_utterance_delay` and `transcription_delay` share one VAD anchor, so they overlap - subtract, never add. (2) `TTSMetrics.acquire_time` and `connection_reused` are useless on this stack: `livekit-agents` initialises them to 0.0/False on the stream and leaves each plugin to fill them in, and `livekit-plugins-fishaudio` 1.7.0 never does. The same two facts do live on `ConnectionPool.last_acquire_time` / `last_connection_reused`, which is what `adapter/tts_pool.py` reads. Also: `ConnectionPool.prewarm()` is one-shot for the life of the pool (`if self._prewarm_task is not None: return`, and the weakref is never cleared), so calling it a second time does nothing at all.

- 2026-08-31: **the budget policy's failure direction is CLOSED, and its word lists are YAML traps.** Three rules from the PR #20 review rework. (1) Any error on the confirmation path (refused echo, broken template) hands over to a human - `BudgetPolicy.abandon()` plus `_route_to_human` - never falls through to the model; a `return None` on that path is the fail-open defect that blocked the PR. (2) `budget_settled` (deterministic policy) and the brief's model-inferred `budget.confirmed` are different sources deliberately named apart; the policy wins wherever they disagree. (3) Word lists in `data/currencies.yaml` must quote y/n words - bare `no` is a YAML boolean and loads as an unmatchable `False`; the loader now rejects non-strings, so an unquoted word fails loudly at startup rather than silently never matching.

- 2026-08-30: **`AllowedFigures.amounts` is not money.** It holds prices and derived instalments, but also every `size_sqft_*` from inventory and the hotline number from the whitelist. The guardrail rightly does not care - a number is a number when you are asking whether it was invented - but VERBALISATION does: an amount's spoken form may swallow an adjacent `AED` because the form names the currency itself, so a currency-naming form on a square footage makes the buyer hear "four hundred and twenty dirhams square feet". Author spoken forms against `currency_amounts` only; whitelist entries carry `kind: currency | quantity | identifier` and it is enforced at load. The hotline is an `identifier` and is still read aloud as a quantity - that is a client fact, tracked on #10, not something to guess. Use `verbalise.spoken_form_gaps()` rather than eyeballing the table.

- 2026-08-29: **a data file with no loader is not configuration, it is a document.** `data/disclosures.yaml`, `data/prerolls.yaml` and `data/lexicon.yaml` were all authored, reviewed in the docs, referenced in prose, and read by nothing. For the disclosure that meant the agent never disclosed it was an AI, in any language, while `prompts.py` told the model the system was handling it - a gap every individual piece of which looked correct. Before treating any `data/*.yaml` as live, grep for a loader. Also: the numeric guardrail DOES work in Arabic and Hindi (`figures.py` normalises Arabic-Indic, extended Arabic-Indic and Devanagari digits plus `٬`/`٫`, verified by execution, and `_BOUNDARY` in `interception.py` already splits on `؟` and `।`) - but the prohibited-language validator does NOT: every pattern in `data/prohibited-patterns.yaml` carries `language: en`, `check_prohibited` ignores that field and applies all patterns to every language, so in Arabic or Hindi script it matches nothing. It catches English code-switched violations only, and "no guaranteed returns" is therefore an English-only claim today.

- 2026-08-29: a currency token written flush against the digits was a live guardrail bypass, and the dangerous half was a FALSE PASS, not a gap: `AED1,985,000` restarted extraction after the comma and validated against the embedded, allowed `985,000`. When touching figure extraction, the rule is that a match never starts inside a number and a letter never blocks one; over-extraction blocks a sentence, under-extraction speaks an unverified one.
